## Confirmed revised sequence

The user requires a Six Boxes performance-solution decision before recommending instructional solutions. The workflow must first establish whether learning, nonlearning interventions, or a combination is justified. This supersedes the proposal to open directly with an e-learning/performance-support recommendation.

1. Review performance influences using the Six Boxes model and the reviewed Analysis evidence.
2. Determine an instructional, noninstructional, combined, or further-investigation route for designer review.
3. Recommend specific interventions aligned with the reviewed influences and route.
4. If e-learning is appropriate, select microlearning, a course, or a mix.
5. Select Storyline 360, Rise 360, or both, with the intended tool recorded for each relevant deliverable/component.

The user approved this revised sequence, Six Boxes review approach, route choices, e-learning format/tool options, and conditional L2 rule. More detailed form interactions and exact field wording continue to be refined section by section.

## Section 1: Performance-solution decision — agreed approach and questions

Reuse Analysis information rather than asking the designer to re-enter it. For each influence, AI can prefill relevant evidence, a potential issue, a suggested response, and unanswered questions. Findings remain hypotheses until reviewed; do not infer personal motivation or capacity from weak performance alone.

| Six Boxes category | Proposed review question |
| --- | --- |
| Expectations and Feedback | Do people know what successful performance looks like, and receive useful feedback? |
| Tools and Resources | Do people have the tools, information, processes, time, and resources needed to perform? |
| Consequences and Incentives | Do consequences and incentives encourage the desired performance or work against it? |
| Skills and Knowledge | What evidence shows that people need to learn knowledge or skills to perform the task? |
| Selection and Assignment (Capacity) | Do assignments match people's capabilities and the demands of the role? |
| Motives and Preferences (Attitude) | What do we know about people's willingness to perform the task and the factors shaping it? |

The boxes categorize interacting influences, not six mutually exclusive solutions. Several interventions may be necessary. Agreed route choices: learning needed, nonlearning response needed, both, or insufficient evidence. The designer reviews evidence and selects the route before detailed instructional drafting.

Official model references checked: https://www.sixboxes.com/Six-Boxes-Model.html and https://www.sixboxes.com/_customelements/uploadedResources/SixBoxes.pdf.

## Section 2: Recommended intervention — revised proposal

After the performance-solution decision, propose an evidence-linked response:

- Recommended approach: targeted learning, performance support, changes to expectations/feedback, tools/processes/resources, incentives, assignment, or a combination as justified by evidence. Do not equate all performance support with instruction.
- Rationale: a short explanation linked to the performance gap, evidence, audience, constraints, and evaluation measures.
- Expected contribution: which learning needs or workplace behaviors the intervention is intended to support.
- Limitations: what the proposed intervention will not resolve and what remains uncertain.

Designer questions/actions:

1. Which intervention would you like to proceed with? Prefill the recommendation and allow an alternative or a return to Analysis.
2. What would you like to change about the recommended approach? Optional explanation; the designer can accept without rewriting it.

Proposed routing: retain nonlearning recommendations, rationale, dependencies, and suggested responsible roles in a concise handoff. Recommendations do not authorize implementing organizational/HR changes. Continue to a written performance-support draft when that is the selected supported deliverable; omit learning/course fields where they are inapplicable. If a nonlearning response outside supported deliverables is selected, stop course drafting and provide the recommendation handoff. For combined responses, define the learning scope and retain required nonlearning actions as dependencies. Pause for evidence collection when the route cannot yet be justified. Any downstream skeleton content remains a proposal and must be checked against the reviewed route.

## Section 3: E-learning format, then authoring tools — agreed

1. Should this e-learning be structured as microlearning, a course, or a mix? AI proposes a structure tied to the performance need, objectives, task complexity, context, and constraints; duration alone must not determine the format.
2. What units/modules are needed and what does each address? Prefill a short proposed outline for review, not a fixed screen-count rule.
3. Which authoring tools should be used: Storyline 360, Rise 360, or both?
4. If both, which components use which tool and how should learners move between them? Do not assume a particular integration or a native project-file export capability. Verify technical feasibility before producing final build instructions.

Use tool-specific storyboard structures per component and preserve approved objectives and assessment links when the format or tool changes.

## Confirmed conditional L2 gate

This supersedes the earlier universal L2-before-Design rule. The first-in-Design Six Boxes decision can establish that no learning is needed.

Agreed resolution: allow entry into the initial performance-solution review with L2 unresolved when applicability has not yet been established. If learning is needed (alone or with other responses), require identified, designer-confirmed L2 measures before proceeding into instructional Design. If there is no learning component, record L2 as “Not applicable — no learning intervention” with rationale, rather than inventing measures. Keep relevant L3/L4 planning. ## E-learning section — agreed field wording

- Designer selection: “How should this e-learning be structured?” Options: microlearning, a course, or a mix.

## Section 4: Learning objectives — agreed, with Bloom's taxonomy

Applies to confirmed learning components. Performance-support-only work without learning outcomes uses task/performance requirements rather than being forced through course-objective fields. A combined solution retains nonlearning dependencies.

AI uses the reviewed performance needs, confirmed L2 measures, audience, and initial unit/module outline to propose editable learning objectives. Carry forward relevant facts; do not require duplicate entry. For each objective, show:

1. What should the learner be able to do after this unit or course?
2. Under what conditions, or using which tools or resources, should they be able to do it?
3. What standard or criteria would demonstrate successful performance?
4. Which L2 learning measure does this objective support? Prefill the mapping for review.
5. Which unit or module should address this objective? Prefill the mapping for review.

Automatically assign stable objective IDs. Give short explanations/examples on request. Preserve links to the underlying workplace behavior and intended result. Proposed wording or performance standards must remain clearly labeled; AI must not invent an organizational requirement or silently change a confirmed L2 measure.

The designer can edit, add, remove, or combine objective proposals. If that changes coverage of a confirmed L2 measure or other linked content, flag the change for review. Detailed assessment tasks/items are defined in the subsequent Design section using the reviewed objectives and L2 measures. The user approved Section 4 and required objectives to use Bloom's taxonomy.

### Confirmed Bloom's requirement and application

- Use revised Bloom's taxonomy for cognitive learning objectives: Remember, Understand, Apply, Analyze, Evaluate, Create.
- Draft objectives using observable action verbs, the actual intended task/content, relevant conditions, and success criteria. Conditions and criteria come from the agreed objective-writing structure; Bloom's supplies cognitive-process alignment rather than a complete objective template by itself.
- Show a proposed Bloom level per objective for designer review. Provide a short reason on request; select a level based on the actual cognitive demand, not the verb alone.
- Select the level needed by the workplace performance and confirmed L2 measure. Do not force every course to cover all six levels or automatically prefer the highest level.
- Assessments and activities must match the intended cognitive demand; a recall-only item does not demonstrate an objective requiring application or judgment. Preserve the reviewed Bloom level with the objective ID through content mapping and storyboard handoff.
- Tag and explain measurable objectives; do not write vague learner-facing objectives such as “understand the procedure” without observable evidence of learning.
- L2 confidence, attitude, and commitment measures remain distinct from demonstrated cognitive/skill achievement. Do not force a cognitive taxonomy label to stand in for evidence of those measures.
- During AI integration for Design, include Bloom-aligned example objectives and mismatch cases in prompts and quality checks, as part of the already agreed iterative review process.

References checked: https://celt.iastate.edu/prepare-and-teach/design-your-course/blooms-taxonomy/ and https://www.uvm.edu/ctl/blooms-taxonomy. Exact UI presentation of the Bloom level and help text remains to be refined.

The user subsequently confirmed this Bloom's requirement and alignment approach without further changes.

## Section 5: Assessments and practice — agreed

AI proposes an editable assessment plan and draft tasks/items using reviewed objectives, their Bloom levels, confirmed L2 measures, selected source material, and the chosen e-learning structure/tools. Define assessments during Design and carry reviewed records into the storyboard. Do not default every objective to a multiple-choice item or assume an arbitrary one-item-per-objective rule.

For each assessment/task, proposed fields and questions:

1. Objective alignment: Which learning objective(s) and L2 measure does this assessment address? Prefill the links; show the reviewed Bloom level for each objective.
2. Purpose: Is this formative practice, a scored assessment, or another form of learning evidence? Keep these distinct; practice and assessment can be separate linked items.
3. Method: What type of question, scenario, demonstration, or work product will provide suitable evidence?
4. Task/item: What exactly will the learner be asked to do? Include the scenario/prompt, instructions, and response options where relevant.
5. Expected performance: What is the correct or acceptable response, or what rubric will be used?
6. Feedback: What explanation or guidance should learners receive for their responses? Draft feedback for each relevant response or performance condition.
7. Scoring: What scoring or success criteria apply? Show only applicable fields; proposals are not approved organizational standards.
8. Attempts and completion: What retry, remediation, and completion rules are needed? Keep item-level rules distinct from course-level completion settings.

AI prefills proposals with source references. The designer can accept, edit, replace, add, or remove draft items. Maintain stable assessment IDs and objective/L2 links. Flag objective coverage gaps, source uncertainty, answer/feedback inconsistencies, mismatched cognitive demand, and tool feasibility issues. An external demonstration requiring observation should not be silently recast as a recall quiz merely to fit the tool.

The alignment matrix will summarize objectives, Bloom levels, L2 measures, and assessment evidence. Placement in the sequence and activity mapping will be refined in the following learning-activities/sequence section. Detailed storyboard placement and implementation instructions are added in Development without silently changing approved assessment intent or criteria.

The user approved the Section 5 questions, fields, and review behavior.

## Section 6: Learning activities and sequence — agreed with enabling-objective decomposition

AI uses reviewed objectives, Bloom levels, assessment/practice records, audience context, source availability, the solution decision, and the initial e-learning structure/tools to prefill an editable learning sequence. Reuse existing practice and assessment records rather than creating duplicates.

Confirmed user refinement: break each main learning objective into smaller enabling objectives to identify the content and instructional support needed for each part and collectively support the main objective. This adds an enabling-objective step before detailed activity/content sequencing. The user approved the general activities/sequence approach with this change; the decomposition fields and coverage approach below were subsequently agreed.

Proposed fields and questions:

1. Objective alignment: Which main and enabling learning objective(s) does this activity support? Prefill the links and show the relevant Bloom levels.
2. Instructional support: What explanation, example, demonstration, or reference will prepare learners to perform the task?
3. Practice: How will learners practice before demonstrating achievement? Reuse the reviewed practice items; allow further proposals where coverage is missing.
4. Sequence: In what order should the content and activities appear within each unit or module?
5. Assessment placement: Where should the reviewed assessments appear in the sequence? Select by assessment ID rather than duplicating content.
6. Workplace transfer: What support will help learners apply this on the job? Carry forward relevant Six Boxes dependencies and approved performance-support decisions; do not automatically expand the project deliverables.

Output: an editable sequence map linking unit/module, main objective, enabling objective, instructional support, activity, existing practice/assessment IDs, and relevant workplace support. The designer can reorder, edit, add, or remove proposed activities. Show source/content gaps; do not invent final content before source mapping.

Check objective and assessment alignment, preparation before assessment, meaningful use of interaction, accessibility, selected tool feasibility, and known scope constraints. Five minutes remains a benchmark, not a mandatory limit. Do not reintroduce the audience-time question removed from Analysis.

If changes affect reviewed objectives or assessments, flag them for review and update the linked records only after designer acceptance. Preserve stable IDs through mapping and storyboard handoff.

### Enabling-objective mapping — agreed

For each main objective, AI proposes the prerequisite knowledge, component skills, decisions, and task steps learners need, based on the reviewed audience and performance context. Convert these into measurable enabling objectives using revised Bloom's taxonomy where appropriate. Assign stable child IDs linked to the main objective, for example LO-1 → EO-1.1. Preserve the main objective's L2/assessment relationships.

For each enabling objective, proposed fields:

- Enabling-objective statement, proposed Bloom level, relevant conditions and success criteria.
- Contribution to the main objective: what part or prerequisite it addresses.
- Essential content and supporting source/reference, with missing content visibly flagged.
- Instructional support: explanation, worked example, demonstration, reference, or another suitable support.
- Practice and feedback: proposed activity or link to existing practice; mark unnecessary repetition rather than forcing a separate activity for every item.
- Evidence of achievement: link to a suitable check or to an existing assessment that covers it. A separate scored question for every enabling objective is not mandatory.
- Prerequisites and suggested sequence, considering audience knowledge.

The designer can edit, add, combine, remove, and reorder enabling-objective proposals. Avoid arbitrary counts, splitting into trivial fragments, or assuming every enabling objective must have a lower Bloom level. If a main objective is already sufficiently focused, propose the smallest meaningful supporting structure rather than padding it.

Coverage review must check that enabling objectives collectively address the main objective without gaps or unnecessary content. Coverage does not by itself demonstrate the integrated performance; retain assessment of the main objective at its intended cognitive/performance level. Flag existing assessment records for review when decomposition reveals a gap; do not silently replace approved assessments.

The resulting hierarchy is main objective → enabling objectives → content/sources and instructional support → practice/evidence → sequence and storyboard locations. The user approved the enabling-objective breakdown, fields, coverage review, and preservation of integrated main-objective assessment. Exact hierarchy UI remains to be designed.

## Section 7: Sources and content mapping — agreed, project-wide source settings

Existing sources and earlier scope information carry forward; do not require duplicate uploads or entry. Confirmed clarification: ask the source questions once for the entire project's content mapping, not for every main or enabling objective. At the objective level, designers review the proposed mapping and resolve specific gaps or conflicts; they may optionally assign a specific source without repeating the questionnaire. An objective-level assignment must not silently enable a source mode or external research excluded by the project settings.

Proposed questions:

1. Source approach: Should the content use provided material, web research, or both?
2. Source selection: Which documents, pasted text, or web pages should be used? Show existing material and allow additional permitted sources.
3. Source preferences: Are there sources or websites to prioritize or exclude? Show for web-enabled modes.
4. Authority and conflicts: Which sources should take precedence if information conflicts? Flag actual conflicts for review; do not silently override an approved project decision.
5. Content boundaries: What content must be included, and what should be excluded? Prefill the relevant earlier scope decisions.
6. Missing content: If an enabling objective lacks supporting content, should the app request designer input, research additional sources where permitted, or leave a visible gap for later resolution? Do not enable web research implicitly under provided-material-only mode.

Proposed editable content map:

- Main objective and enabling-objective IDs, with reviewed Bloom levels available.
- Essential content needed for the enabling objective.
- Source reference: document and page/section where available, or URL and supporting passage/section.
- Instructional support and linked practice/assessment evidence from existing records.
- Intended unit/module and planned storyboard screen/block/support section, or an explicit unassigned location where placement is not yet resolved.
- Coverage status: supported, partially supported, missing, or conflicting; plus the issue and proposed next action.

AI should propose content selection and source matches, not indiscriminately summarize every file. Verify that references support the claims attributed to them; a working link is insufficient. Distinguish source facts from proposed instructional treatments, hypothetical scenarios, and unconfirmed assumptions. Keep gaps and conflicts visible and preserve source/ID relationships through review and export.

Source selection and preferences are editable designer controls. Content mapping must not silently change reviewed objectives, assessments, or success criteria. Flag affected records if new evidence calls them into question. The user approved Section 7 with the project-wide source-question clarification.
