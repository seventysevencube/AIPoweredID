## Current workflow

1. Analysis form → editable Analysis brief → explicit version handoff.
2. Six Boxes review → confirmed learning, nonlearning, combined, or further-investigation route.
3. AI-supported solution choice: e-learning, performance aid, both, or further investigation, justified by Analysis evidence and reviewed by the designer.
4. Confirm the corresponding deliverables and refine their scope. The renamed output is **Written job aid / performance-support draft**, meaning complete written content for the aid.
5. Only for e-learning: microlearning/course/mix → initial unit/component outline → Storyline/Rise/both, including allocation and proposed connections.
6. For learning components: observable main objectives with revised Bloom’s levels and meaningful enabling objectives → defined assessments in Design → activities/sequence and source/content mapping → reviewed Design plan.
7. Generate Development sample → review/refine → complete written draft/storyboard → review, sharing, and PDF/editable PowerPoint export.

Evaluation planning covers L2/L3/L4. Learning routes require defined, designer-confirmed L2 measures. A performance aid can support learning, workplace performance, or both; review its purpose and explicitly update linked route/evaluation records when needed. A solely nonlearning route retains relevant L3/L4 measures and records L2 as not applicable with rationale. It uses task/performance requirements rather than course objectives and learning assessments. Investigation holds drafting. Nonlearning recommendations outside supported written deliverables receive a recommendation handoff.

## Validation and limits

Fragments have scoped product styles, native controls, guarded local interaction state, and no project/backend network requests. Structural checks and JavaScript syntax checks are performed. Standalone versions are generated with the preview renderer. No browser visual QA, assistive-technology testing, WCAG conformance validation, or live autosave/recovery testing is claimed. The agreed WCAG 2.2 AA target remains an implementation and validation requirement.

Exports contain default illustrative sample content, not saved user interaction snapshots, real uploaded documents, or production credentials. Previews are independent screens; they do not transfer edits between files. Standalone preview state is local to the preview environment and is not the product’s promised autosave/recovery system. External preview libraries may require internet access. Source/answer verification and actual AI behavior remain future integration work.
